# AI 漫剧工作台重构设计

- Date: 2026-06-06
- Topic: AI 漫剧工作台四步流程重构与提示词文件体系规划
- Status: 已确认需求，待进入实施规划

## 1. 背景

当前项目已经具备 Electron + React + Vite 的桌面端基础能力，并完成了模型配置、项目管理、自动更新、多平台发布和五段式生成能力的 MVP 实现。现阶段产品形态更接近能力演示工具，离长期使用的创作工作台还有明显差距。

本次重构目标是参考用户提供的桌面界面，升级为更完整的 AI 漫剧创作工作台。重点包括四步流程重构、提示词管理模块、安装与文件保存体验、统一的本地配置体系、品牌视觉升级，以及围绕风格、比例、质量、平台、资产和分镜提示词的完整创作链路。

## 2. 设计目标

本次设计聚焦以下目标：

1. 将现有五段式能力重组为四步工作流：`视频设置 -> 剧本编辑 -> 资产库 -> 分镜脚本`
2. 增加 Windows 安装路径选择能力
3. 在应用内提供全局唯一输出目录设置，并按项目名组织所有生成产物
4. 增加系统级提示词管理模块，按文件组织模板
5. 支持风格、比例、质量、平台等参数，并采用“全局默认 + 项目覆盖”模式
6. 重构信息架构，使界面形态尽量贴近参考图
7. 将本地文件和本地配置作为核心持久化方式
8. 更换应用图标、界面 Logo 和静态启动页品牌视觉

## 3. 已确认的需求边界

### 3.1 安装与程序视觉

- Windows 安装包采用 `NSIS 自定义安装`
- 用户在安装过程中可以选择安装路径
- 图标重构范围包括：
  - 应用程序图标
  - 应用内左上角 Logo
  - 静态品牌启动页
- 新图标视觉方向为：`影视场记板 / 导演工具感`
- 启动页首版采用静态品牌启动页，无复杂动画

### 3.2 保存路径与项目模型

- 应用提供一个 `全局唯一输出目录`
- 全部项目和全部生成阶段的产物统一保存到该目录
- 输出目录按 `项目名` 分目录组织
- 项目采用 `应用内项目库` 模式管理
- 数据保存方式采用 `本地文件 + 本地配置`
- 保存交互采用 `自动保存为主`，顶部保留显式保存入口

### 3.3 主流程结构

- 四步流程固定为：
  1. 视频设置
  2. 剧本编辑
  3. 资产库
  4. 分镜脚本
- 参考图中的左侧流程导航、顶部操作区、主区布局、提示词管理模块都是本次重构的重要参照

### 3.4 提示词管理

- 提示词模块先做成 `系统模板库`
- 模板分类采用参考图版 `6 类`：
  - 系统提示词
  - 角色提取
  - 场景提取
  - 资产生成
  - 分镜后缀
  - 大纲生成
- 提示词编辑能力采用：`文本模板 + 变量 + 分段结构化编辑`
- 变量体系采用扩展集：
  - `{style}`
  - `{aspectRatio}`
  - `{quality}`
  - `{projectName}`
  - `{episodeTitle}`
  - `{seconds}`
  - `{platform}`
  - `{character}`
  - `{scene}`
  - `{prop}`
  - `{shotType}`
  - `{cameraMovement}`
- 提示词按文件处理，而不是只存成配置字段
- 提示词文件内容规范直接参考用户提供的 `提示词.txt`

### 3.5 视频参数与排版

- 参数采用 `全局默认 + 项目可覆盖`
- 画面风格首版采用固定预设风格
- 首版比例采用：`16:9`、`9:16`、`1:1`、`21:9`
- 质量采用三级预设：`标准`、`高`、`超高`
- 平台参数纳入首版，作为提示词拼装上下文
- 排版功能首版同时覆盖：
  - 提示词拼装排版
  - 分镜编辑界面排版

### 3.6 剧本与资产链路

- 剧本编辑页通过大纲信息触发 AI 一键生成分集
- 分集生成方式确定为：`AI 根据大纲一键生成分集`
- 资产提取来源确定为：`从分集内容提取`
- 资产库首版包含：
  - 角色
  - 场景
  - 道具
- 分镜脚本页的首版核心目标为：`生成和编辑分镜提示词`
- 导出首版同时支持：
  - 导出分镜提示词与脚本文本
  - 导出项目完整资料包

## 4. 推荐方案

本次重构采用以下方案：

### 方案 A：主框架重构 + 本地配置体系升级 + 轻量生成链路重组

这是本次推荐方案，原因如下：

1. 用户目标已经从 MVP 演示工具转向长期使用的内容创作工作台
2. 参考图重点体现的是信息架构、参数体系、提示词体系和资产沉淀，当前项目短板也正集中在这些位置
3. 当前已有生成能力、模型配置和桌面端基础，适合保留底层能力并重塑产品结构
4. 首版仍需控制复杂度，因此优先重构产品壳层、页面结构、配置体系与数据模型，底层生成服务可阶段性复用现有能力

### 备选方案

#### 方案 B：渐进增强

- 保留现有页面结构
- 逐步加入新能力
- 代价是界面会继续碎片化，与参考图差距大

#### 方案 C：先做后台能力层

- 先做本地文件存储、提示词引擎和项目配置模型
- 后续再重做界面
- 代价是短期产品形态提升不明显

## 5. 信息架构设计

新版应用采用三层布局：

1. 顶部全局操作栏
2. 左侧四步导航
3. 右侧主工作区

### 5.1 顶部全局操作栏

顶部栏承载项目级和应用级动作，包括：

- 返回项目列表
- 当前项目名和标签
- 提示词管理入口
- 保存
- 导出项目
- 导出脚本文本
- 账号和退出

### 5.2 左侧四步导航

左侧固定四步工作流：

1. `视频设置`
2. `剧本编辑`
3. `资产库`
4. `分镜脚本`

每一步包含标题和说明文案，用于表达当前阶段的产出目标。

### 5.3 右侧主工作区

#### 视频设置

负责项目参数与生成基线，包括：

- 风格
- 比例
- 质量
- 平台
- 时长
- 自动拼装关键词预览

#### 剧本编辑

负责结构化大纲信息和分集生成，包括：

- 标题
- 主题
- 简介
- 一键生成分集
- 分集列表查看与展开

#### 资产库

负责管理从分集内容中提取出的角色、场景、道具，并支持人工确认后入库。

#### 分镜脚本

负责组合参数、资产、分集内容和提示词文件，生成并编辑分镜提示词，并支持导出。

### 5.4 提示词管理模块

提示词管理模块作为独立入口，从顶部操作区进入。界面形态采用参考图中的弹窗式或独立工作区式结构：

- 左侧：六类提示词模板列表
- 右侧：结构化编辑区
- 顶部：保存、恢复默认等操作

界面层体现为“模板分类与编辑体验”，底层体现为“模板文件集合管理”。

## 6. 提示词文件体系设计

### 6.1 文件组织原则

提示词体系采用 `系统模板文件库` 模式。首版包含 6 类独立文件：

- 系统提示词
- 角色提取
- 场景提取
- 资产生成
- 分镜后缀
- 大纲生成

每一类对应一个独立文本文件。系统启动时先读取默认模板目录，再加载用户模板目录中的覆盖文件。用户保存后写入本地用户模板目录。

### 6.2 文件内容规范

提示词文件内容直接参照用户提供的 `提示词.txt`，采用如下表达特征：

- 标题分段
- 规则列表
- 示例内容
- 输出格式说明
- 附加约束
- 变量占位符
- 长文本知识库

产品层面不重构这种格式，而是以稳定加载、展示、编辑、保存和用于拼装为核心目标。

### 6.3 编辑方式

编辑器保留原始文本编辑视角，同时提供文本语义增强：

- 标题识别
- 变量高亮
- 示例段识别
- 规则段识别
- 约束段识别

这里坚持 `文件内容优先` 原则，界面只增强编辑体验，不压缩文件表达能力。

### 6.4 变量与拼装上下文

变量采用扩展集，生成时按上下文注入实际值。拼装链路如下：

1. 读取系统提示词文件
2. 读取对应任务的附加提示词文件
3. 读取全局默认参数
4. 读取项目覆盖参数
5. 读取当前分集内容与资产上下文
6. 解析变量并拼装最终执行提示词

### 6.5 内容执行原则

模板文件作为完整提示词资产使用，不拆解成少数字段。比如：

- 系统提示词保留时长、比例、风格、运镜规则、音效约束
- 角色提取模板保留 JSON 输出格式和字段要求
- 分镜类模板保留对话格式、时间分配、附加约束等要求

## 7. 数据模型与本地持久化设计

应用数据分为三层：

1. 应用配置
2. 项目数据
3. 生成产物

### 7.1 应用配置

应用配置保存在本地配置目录，包含：

- 全局默认参数
- 输出目录
- 提示词模板文件索引
- 当前账号信息
- 界面偏好

### 7.2 项目数据

项目数据由应用内项目库统一管理，包含：

- 项目标题
- 标签
- 主题
- 简介
- 项目级参数覆盖
- 分集结果
- 资产引用
- 导出记录

### 7.3 生成产物目录

统一输出目录采用以下结构：

```text
输出根目录/
  项目名/
    script/
    assets/
    storyboard/
    exports/
```

目录职责如下：

- `script/`: 大纲、分集文本、导出的小说或脚本文本
- `assets/`: 角色、场景、道具描述、生成图、索引信息
- `storyboard/`: 分镜提示词、镜头结果、中间文本
- `exports/`: 完整项目导出包

### 7.4 模板文件与项目解耦

提示词文件单独保存在模板目录中，不混入项目产物目录。项目中只记录：

- 当前使用的模板组标识
- 项目级变量值
- 项目覆盖参数

系统运行时优先读取用户模板目录，缺失时回退默认模板目录。

## 8. 生成链路设计

新版生成链路重组为以下流程：

1. 用户在 `视频设置` 中维护全局默认或项目覆盖参数
2. 用户在 `剧本编辑` 中填写标题、主题、简介
3. 系统基于大纲信息执行 AI 一键生成分集
4. 系统从分集内容中提取角色、场景、道具，进入 `资产库`
5. 用户确认或修正资产内容
6. 系统在 `分镜脚本` 中组合参数、资产、分集和提示词文件，生成可编辑的分镜提示词
7. 用户导出脚本文本或完整项目资料包

### 8.1 参数继承规则

参数采用 `项目优先，全局兜底` 原则：

1. 先读取全局默认设置
2. 再读取项目覆盖值
3. 生成最终执行上下文

### 8.2 分镜提示词组合规则

分镜提示词生成时，系统应组合：

- 系统提示词文件
- 分镜后缀文件
- 当前项目参数
- 当前分集内容
- 当前资产引用

## 9. 异常处理设计

首版需要重点处理四类异常。

### 9.1 配置缺失

场景包括：

- 输出目录未设置
- 提示词文件缺失
- API 配置不完整

处理方式：

- 在进入相关步骤时直接提示
- 提供修复入口
- 阻止继续执行需要完整配置的操作

### 9.2 文件异常

场景包括：

- 模板文件读取失败
- 编码异常
- 用户误删模板文件

处理方式：

- 回退默认模板
- 显示警告
- 保留错误详情供排查

### 9.3 生成异常

场景包括：

- AI 返回错误
- 结构化输出不符合预期
- 资产提取 JSON 解析失败

处理方式：

- 保留原始返回结果
- 提示用户重试
- 支持手工修正结果

### 9.4 导出异常

场景包括：

- 目录不可写
- 文件名冲突
- 项目名包含非法字符

处理方式：

- 落盘前先校验
- 自动处理安全文件名
- 明确提示导出失败原因

## 10. 验证策略

首版验证重点如下：

1. 提示词文件可以正确加载、保存、恢复默认
2. 全局参数与项目覆盖参数能按优先级正确继承
3. 生成产物能稳定落到统一输出目录的项目子目录
4. 四步流程中的关键空状态、异常状态和自动保存行为符合预期
5. 剧本大纲、分集生成、资产提取、分镜提示词导出链路可以走通

## 11. 实施建议

建议后续实施按以下顺序拆分：

1. 本地配置层与项目库层重构
2. 提示词文件系统与模板目录设计
3. 视频设置页重构
4. 剧本编辑页与分集数据模型重构
5. 资产库与提取结果承接
6. 分镜脚本页与导出能力重构
7. NSIS 安装配置、图标与启动页接入

## 12. 暂不进入首版的事项

以下内容不纳入本次首版设计范围：

- 云同步和多端协作
- 复杂动画启动页
- 用户自定义变量体系
- 高级镜头排序与复杂拖拽编排
- 完整的模板版本管理系统
- 在线模板市场或模板分享体系

## 13. 结论

本次重构将现有项目升级为完整的 AI 漫剧工作台，核心变化不是单点功能叠加，而是围绕四步工作流、提示词文件体系、本地文件持久化和项目级创作链路做整体结构调整。完成这一轮重构后，产品形态、数据结构和使用路径都会更接近真实创作工具，并为后续继续扩展资产体系、分镜编辑能力和导出能力打下基础。
